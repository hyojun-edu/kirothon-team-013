# 장보기 도우미

마트 "할인가"가 내가 전에 산 가격보다 비싼지, 장 보는 자리에서 바로 확인하게 해 주는 모바일 웹앱이에요.

## 1. 문제 정의

### 대상 사용자
장을 자주 보면서 "이 가격이 정말 싼 건가?"를 매번 고민하는 사람.

### 문제 상황
- 마트에서 "할인"이라고 붙어 있어도, 비교해 보면 예전에 시장에서 산 가격이나 온라인 최저가보다 비싼 경우가 많아요.
- 그런데 전에 얼마에 샀는지, 그때 용량이 얼마였는지 기억하기 어려워요.
- 온라인 최저가를 한 번 검색해도 다음 장보기 때는 잊어버려요.
- 용량이나 묶음 개수가 달라서 가격을 눈으로 비교하기도 어려워요.

### 기존 방식과 한계
- 기억이나 메모에 의존하면 용량과 묶음이 다른 상품을 정확히 비교할 수 없어요.
- 가격 비교 사이트는 온라인 가격 위주예요. 내가 직접 산 오프라인 가격은 남지 않아요.
- 가계부 앱은 지출 합계를 기록해요. 상품별 단위가격 비교는 도와주지 않아요.

### 목표
장 볼 때마다 가격을 조금씩 기록해 "나만의 가격 DB"를 쌓고, 용량이 달라도 단위가격(100g당 등)으로 바로 비교하게 해요. 나중에는 개인 기록을 모아 오프라인 최저가 DB로 키울 수 있게 데이터 구조를 설계했어요.

| 단위가격 계산 (100g, 100ml, 1개 기준, 배송비 포함) | 용량과 묶음 개수가 달라서 비교가 어려움 | `src/domain/unitPrice.ts`, `src/domain/units.ts` |
| 검색 결과 화면: 단위가격 낮은 순 목록, 순위, 최저가 강조 | 지금 가격이 싼지 한눈에 알기 어려움 | `src/features/results/`, `src/domain/compare.ts` |

| 기간 필터 (전체 / 최근 1년 / 90일 / 30일): 오래된 가격을 목록과 순위 계산에서 빼기 | 몇 달 전 가격과 비교하면 지금 싼지 오해함 | `src/domain/compare.ts`, `src/components/PeriodSelect.tsx` |
| 비교 프리셋: 똑같은 상품 / 같은 상품 용량 무관 / 같은 품목 전체 | 비교 범위를 상황에 따라 바꾸고 싶음 | `src/domain/compare.ts` |
| 내 상품 비교 바 (저장 전에 순위와 최저가 차이 표시) | 사기 전에 판단하고 싶음 | `src/features/register/` |
| 품명 자동완성 시 이전 사진 불러오기 | 같은 상품 사진을 매번 다시 찍기 번거로움 | `src/features/register/`, `src/data/repositories.ts` |
| 온라인 가격 검색 (구글 새 탭) 후 미리 채운 등록 | 온라인 가격을 검색한 뒤 같은 정보를 다시 입력하기 번거로움 | `src/features/search/`, `src/domain/searchQuery.ts`, `src/domain/prefill.ts` |
| 최신가격 다시 검색 (온라인 기록 갱신, 가격 이력 보존) | 예전 온라인 가격이 지금도 맞는지 알기 어려움 | `src/features/detail/`, `src/domain/prefill.ts` |
| 오프라인 사용, 홈 화면 설치 (PWA) | 마트 안에서 통신이 약함 | `src/pwa/`, `vite.config.ts` |

## 3. 사용 시나리오

0. 마트에서 두부를 보고 홈 "빠른 비교"에 품명을 입력해요. 후보(사진, 용량×번들, 최근 가격, 판매처)를 고르면 칸이 채워지고, 가격만 고쳐 "비교하기"를 누르면 저장 없이 순위가 보여요. 마음에 들면 "이 가격으로 등록".
1. 마트에서 두부를 보고 "등록"을 눌러요. 품명을 입력하면 홈과 같은 후보 목록이 열리고, 고르면 브랜드, 원산지, 용량과 "이전 가격"이 채워지고 이전 사진도 불러와져요.
2. 가격(3,480원)과 번들(2개)을 입력하면, 저장하기 전에 "12건 중 5위" 같은 순위와 최저가와의 차이가 바로 보여요.
3. 불러온 사진을 그대로 쓰거나 새로 찍어 저장하면 두부 비교 목록으로 가요. 단위가격(580원/100g) 낮은 순으로 보이고, 브랜드나 원산지 필터로 조건부 최저가를 찾고, "기간"을 "최근 90일"로 바꾸면 오래된 가격은 빠져요.
4. 온라인 가격이 궁금하면 "온라인 가격 검색"을 눌러요. 구글이 열리고, 돌아와서 "온라인 가격 등록"을 누르면 상품 정보가 채워져 있어서 가격, 판매처, 배송비, 사진만 입력하면 돼요.
5. 몇 주 뒤 온라인 기록에서 "최신가격 다시 검색"을 누르면 같은 방식으로 새 가격이 쌓이고, 이전 가격은 이력으로 남아요.

## 4. 기대 효과

- 300g × 2개 3,480원은 580원/100g이고, 400g × 1개 2,900원은 725원/100g이에요. 두 상품은 용량이 달라서 눈으로는 비교가 어렵지만, 앱은 앞의 상품이 약 20% 저렴하다고 바로 보여 줘요.
- 비교 목록은 1,000건 기록에서 필터를 바꿔도 300ms 안에 반영돼요 (테스트로 확인).

## 5. 차별점

| 비교 대상 | 한계 | 장보기 도우미 |
|---|---|---|
| 가격 비교 사이트 | 온라인 가격 위주. 내가 산 오프라인 가격이 없음 | 내가 직접 산 가격을 기록하고, 온라인 가격도 같은 목록에서 비교 |
| 가계부 앱 | 지출 합계 중심. 상품별 단위가격 비교 없음 | 용량과 묶음이 달라도 단위가격으로 비교 |
| 메모, 사진첩 | 검색과 계산이 안 됨 | 사진이 가격표 스냅샷으로 남고, 계산과 정렬은 앱이 함 |

- 같은 품목 안에서 브랜드, 원산지, 번들 조건을 골라 "조건부 최저가"를 찾아요.
- 서버 없이 기기에만 저장해서 오프라인에서도 쓸 수 있어요.
- 개인별 데이터를 나중에 합칠 수 있도록 모든 기록에 UUID, 시각, 소유자 필드를 둬요.

## 6. 설치와 실행

필요: Node.js 20 이상.

```bash
# 1. 의존성 설치
npm install

# 2. 개발 서버 실행 (코드를 고치면 바로 반영돼요)
npm run dev
#    -> http://localhost:5173

# 3. 빌드 후 미리보기 (실제 배포 결과물을 확인해요)
npm run build
npm run preview
#    -> http://127.0.0.1:4173
```

| 명령 | 주소 | 용도 |
|---|---|---|
| `npm run dev` | http://localhost:5173 | 개발. 코드를 고치면 화면이 바로 바뀌어요 |
| `npm run preview` | http://127.0.0.1:4173 | 빌드 결과 확인. 홈 화면 설치와 오프라인 동작은 여기서 확인해요 |
| `npm run demo` | http://127.0.0.1:4174 | 데모. 샘플 데이터(두부 등 품목 5개)가 들어 있는 앱으로 제출 영상을 찍어요. 주소 끝에 `?reset=1`을 붙이면 처음 샘플 상태로 돌아가요 |

- 개발 서버는 5173번 포트가 이미 쓰이고 있으면 다른 번호(5174 등)로 열려요. 터미널에 나오는 주소를 보세요.
- 미리보기는 4173번 포트로 고정이에요. 이미 쓰이고 있으면 실행이 멈춰요.
- 종단 테스트(`npm run test:e2e`)는 미리보기 서버를 자동으로 띄워요. 미리 켜 둘 필요가 없어요.

모바일 화면은 브라우저 개발자 도구에서 폭 360px로 보면 돼요.
