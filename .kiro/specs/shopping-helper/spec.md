# 장보기 도우미 (Shopping Helper) — 모바일 웹앱 스펙

## 1. 목적
마트 "할인" 가격이 과거 시장 구매가나 온라인 최저가보다 비싼지 현장에서 바로 확인한다.
사용자가 장을 볼 때마다 가격을 조금씩 기록해 "나만의 가격 DB"를 쌓는다.
향후 개인 데이터를 모아 오프라인 최저가 DB로 확장할 수 있게 데이터 구조를 설계한다.

## 2. 범위
### MVP 포함
- 가격 기록 등록 (사진 필수, 자동완성, 해당사항 없음 처리)
- 품목별 단위가격 비교 목록 (최저가 순)
- 브랜드 / 원산지 / 번들묶음 multi-select 필터
- 모바일 우선 UI, 한 손 입력

### MVP 제외 (향후)
- 계정, 다중 사용자 데이터 통합, 서버 동기화
- 온라인 최저가 자동 크롤링 (온라인 가격은 외부 검색 후 사용자가 직접 입력)
- 바코드/OCR 자동 인식
- 가격 알림, 통계 차트

## 3. 용어
| 용어 | 뜻 | 예 |
|---|---|---|
| 품목 | 상품 종류 | 두부 |
| 품명 | 상품 이름 (없을 수 있음) | 국산콩으로 만든 두부 |
| 단위용량 | 1개(포장 1단위)의 양 | 300g |
| 포장단위 | 판매 단위 | 개, 팩, 봉 |
| 번들묶음 | 한 번에 파는 묶음 개수 | 2개 |
| 총용량 | 단위용량 × 번들묶음 | 600g |
| 단위가격 | 가격 ÷ 총용량 (기본 100g/100ml 또는 1개당) | 580원/100g |

## 4. 입력 항목 (가격 기록)
| 필드 | 필수 | 해당사항 없음 허용 | 비고 |
|---|---|---|---|
| 사진 | 필수 | 아니오 | 상품 식별 + 가격표 스냅샷. 카메라 촬영/갤러리 선택. 품명 자동완성으로 기존 상품을 고르면 이전 사진이 미리 채워진다 (5절) |
| 품목 | 필수 | 아니오 | 자동완성 |
| 포장단위 | 필수 | 아니오 | 개/팩/봉/kg 등 |
| 번들묶음 | 필수 | 아니오 | 기본값 1 |
| 가격 | 필수 | 아니오 | 원, 정수 |
| 판매처 | 필수 | 아니오 | 자동완성 (예: 이마트 구로점) |
| 날짜 | 필수 | 아니오 | 자동 입력(오늘), 수정 가능 |
| 품명 | 선택 | 예 | 농산품 등 품명 없으면 "해당사항 없음" |
| 원산지 | 선택 | 예 | 국산 / 수입(국가) / 해당사항 없음 |
| 브랜드 | 선택 | 예 | |
| 단위용량 | 선택 | 예 | 숫자 + 단위(g, kg, ml, L, 개). 없으면 단위가격은 개당만 계산 |
| 배송비 | 선택 | 온라인 판매처만 표시 | 단위가격 계산 시 가격에 합산 |

- "해당사항 없음"은 빈 값과 다르다. 별도 상태(N/A)로 저장한다.
- 입력 순서는 품명부터 시작한다. 품명을 먼저 입력해야 자동완성으로 이전 사진까지 불러올 수 있기 때문이다. 사진 칸은 맨 아래에 두되, 불러온 사진은 품명을 고른 즉시 보인다. 농산품은 "해당사항 없음" 체크 후 품목으로 바로 진행한다.

## 5. 자동완성 동작
1. 품명 입력 시 기존 등록 상품을 자동완성 목록으로 보여준다.
2. 선택하면 품목, 원산지, 브랜드, 포장단위, 단위용량, 번들묶음을 자동 채운다. 사용자는 수정 가능.
3. 가격은 선택한 후보의 가장 최근 가격으로 미리 채운다. "이전 가격" 표시를 붙이고 사용자가 고칠 수 있다. 판매처는 자동으로 채우지 않는다 (날짜는 오늘).
   - 자동완성 후보를 고를 때 보이는 정보와 고르는 규칙은 15.2를 따른다.
3-1. **사진은 불러온다.** 자동완성으로 기존 상품을 고르면 그 상품의 가장 최근 기록 사진을 사진 칸에 미리 채운다.
   - 같은 상품인지 눈으로 바로 확인하는 용도다.
   - 불러온 사진은 필수 사진 입력을 채운 것으로 본다. 그대로 저장할 수 있다.
   - 사용자는 "다시 촬영" 또는 "갤러리에서 선택"으로 바꿀 수 있다. 불러온 사진에는 "이전 사진" 표시를 붙인다.
   - 사진 파일은 복사하지 않고 같은 사진을 가리킨다. 새로 올리면 새 사진으로 저장한다.
   - 이전 사진이 없는 상품이면 사진 칸은 비어 있다.
3-2. 아래 경우에는 사진을 불러오지 않고 비운다: "온라인 가격 등록", "이 기록으로 새로 등록", "최신가격 다시 검색". 이 경우 사진은 새 가격표/화면 캡처이기 때문이다.
4. 품명이 N/A이면 품목 자동완성으로 같은 흐름을 제공한다.
5. 판매처는 이전 입력값을 자동완성한다. 온라인 판매처로 표시된 곳만 배송비 입력란을 연다.

## 6. 단위 환산 규칙
- 총용량 = 단위용량 × 번들묶음.
- 총가격 = 가격 + 배송비(없으면 0).
- 단위가격 = 총가격 ÷ 총용량.
- 표시 기준: 무게는 100g, 부피는 100ml, 개수는 1개.
- kg→g, L→ml로 내부 환산. 무게와 부피는 서로 비교하지 않는다.
- 단위가 다른 기록(g 대 개)은 같은 목록에서 비교 불가 표시를 하고 하단에 분리한다.
- 단위용량이 N/A인 기록은 번들묶음 기준 개당 가격으로만 비교한다.

## 7. 검색 결과 화면 (비교 목록)
품목을 고르면 해당 품목의 기록을 **단위가격 낮은 순**으로 보여준다. 이 화면이 앱의 핵심이다.

### 7.1 화면 구성 (위에서 아래)
| 영역 | 내용 | 필수 |
|---|---|---|
| A. 헤더 | 품목명, 전체 기록 건수, 뒤로가기 | 필수 |
| B. 내 상품 비교 바 | 지금 보는 상품의 단위가격, 순위("12건 중 5위"), 최저가와 차이(원, %) | 등록 화면에서 진입했을 때 필수. 없으면 숨김 |
| C. 프리셋 탭 | "똑같은 상품" / "같은 상품, 용량 무관" / "같은 품목 전체"(기본) | 필수 |
| D. 필터 바 | 브랜드, 원산지, 번들묶음 multi-select 버튼 + 적용된 필터 칩 + "전체 해제" | 필수 |
| E. 기록 목록 | 7.2의 행. 맨 위 1위 카드가 현재 조건의 최저가다 (별도 최저가 카드는 두지 않는다) | 필수 |
| F. 비교 불가 구역 | 단위가 달라 비교할 수 없는 기록 | 해당 기록이 있을 때 |
| G. 하단 고정 버튼 | "가격 등록", "온라인 가격 검색" | 필수 |

### 7.2 목록 행 (기록 1건)
| 항목 | 표시 | 비고 |
|---|---|---|
| 순위 | 1, 2, 3… | 필터 적용 후 기준 |
| 사진 | 썸네일 (정사각, 탭하면 확대) | 필수 표시 |
| 단위가격 | 예: 580원/100g | 행에서 가장 크고 굵게 |
| 가격, 용량×번들 | 예: 3,480원 · 300g×2 | 단위가격 아래 |
| 품명, 브랜드 | 품명이 N/A이면 품목명 | |
| 원산지 | 국산 / 수입(국가) | N/A이면 생략 |
| 판매처 | 온라인이면 "온라인" 배지 | |
| 배송비 | 온라인이고 배송비가 있으면 "배송비 포함" 표시 | 단위가격에 이미 반영 |
| 날짜 | YYYY.MM.DD, 90일 넘으면 흐리게 + "오래된 가격" | |
- 행을 탭하면 기록 상세로 이동한다. 상세에서 "이 기록으로 새로 등록", "최신가격 다시 검색"(온라인만)을 쓴다.

### 7.3 정렬과 표시 규칙
- 기본 정렬: 단위가격 오름차순. 같으면 최신 날짜 먼저.
- 정렬 변경(MVP): 단위가격순(기본) / 최신순.
- 같은 상품+판매처는 최신 기록만 표시. "이전 기록 보기"로 펼친다.
- 최저가 1위 행은 색상과 "최저가" 배지로 강조한다 (색만으로 구분하지 않는다).
- 내 상품이 목록에 있으면 해당 행에 "내 상품" 표시를 하고 필요 시 스크롤해 보여준다.
- 목록은 한 번에 20건, 아래로 스크롤하면 더 불러온다.

### 7.4 상태별 화면
| 상태 | 화면 |
|---|---|
| 기록 0건 | "아직 기록이 없어요" + "가격 등록", "온라인 가격 검색" 버튼 |
| 필터 결과 0건 | "조건에 맞는 기록이 없어요" + "필터 해제" 버튼 |
| 기록 1건 | 목록 1행 + "비교할 기록이 더 필요해요" 안내 |
| 비교 불가 기록 있음 | 영역 F에 "단위가 달라 비교할 수 없어요"와 함께 목록 |
| 불러오는 중 | 행 모양 스켈레톤 |

### 7.5 터치와 성능
- 모든 버튼과 행의 터치 영역은 44px 이상.
- 필터 변경 결과는 300ms 안에 목록에 반영한다 (기록 1,000건 기준).
- 필터와 프리셋 선택은 화면을 벗어났다 돌아와도 유지한다 (같은 품목 안에서).

### 세 가지 비교 시나리오
| # | 시나리오 | 구현 방식 |
|---|---|---|
| 1 | 용량까지 동일 상품 | 같은 품명 + 같은 브랜드 + 같은 단위용량 기록만 보기 (프리셋 "똑같은 상품") |
| 2 | 같은 상품, 번들/용량만 다름 | 같은 품명 + 브랜드, 단위가격으로 정렬 (프리셋 "같은 상품, 용량 무관") |
| 3 | 같은 품목, 품명/브랜드/원산지 다름 | 품목 전체 + 필터로 좁힘 (기본 보기) |

### 필터 (multi-select)
- 브랜드: 해당 품목 기록에 존재하는 값만 표시. "해당사항 없음"도 선택지.
- 원산지: 국산 / 수입 전체 / 수입 국가별. 국가 구분이 필요 없으면 "수입" 하나로 묶어 선택 가능.
- 번들묶음: 1, 2, 3… 존재하는 값만 표시.
- 필터는 AND로 결합하고, 각 필터 내부는 OR.
- 필터를 적용하면 목록 맨 위의 1위 카드가 그 조건의 최저가다. 이때 1위 카드 배지는 "조건 내 최저가"로 바꾼다 (필터가 없으면 "최저가").
- 적용 중인 필터는 칩으로 표시하고 개별 해제 가능.

### 현재 상품과 비교
- 등록 화면에서 가격 입력 직후 "지금 이 가격" 의 단위가격과 해당 품목 내 순위(예: 12건 중 5위)를 즉시 보여준다.
- 기존 최저가 대비 차이(원, %)를 표시한다.
- 저장 전에도 확인 가능해야 한다 ("저장 없이 비교만" 버튼).

### 온라인 가격 검색 후 이어서 등록
온라인 기록이 DB에 있든 없든, 사용자는 언제든 온라인 가격을 직접 검색해 볼 수 있어야 한다.

**진입점**: 비교 목록 상단, 기록 상세, 가격 등록 화면(가격 입력 전후)에 "온라인 가격 검색" 버튼.

**검색 방식 (MVP)**
- 앱이 가격을 가져오지 않는다. 구글 검색 결과 페이지를 새 탭으로 연다 (`https://www.google.com/search?q=<검색어>`). 특정 쇼핑몰은 직접 열지 않는다.
- 검색어는 현재 상품 정보로 자동 조합한다: `브랜드 + 품명(없으면 품목) + 단위용량 + "가격"`. 사용자가 열기 전에 수정할 수 있다.
- 검색 결과에서 온라인몰 상세 페이지로 들어가 가격을 확인하는 것은 사용자가 직접 한다.
- 판매처 이름은 사용자가 등록 화면에서 직접 입력/선택한다 (자동 제안 없음).

**최신가격 다시 검색 (온라인 기록 갱신)**
- 온라인 판매처 기록의 상세 화면에 "최신가격 다시 검색" 버튼을 둔다.
- 누르면 그 기록의 상품 정보로 구글 검색을 연다. 검색어에 판매처 이름이 있으면 함께 넣는다.
- 돌아와서 "온라인 가격 등록"을 누르면 아래 "돌아와서 등록"과 같은 흐름이다. 단, 이 경우 **판매처, 배송비도 원래 기록 값으로 미리 채운다.** 가격, 사진만 비운다.
- 저장하면 원래 기록은 그대로 두고 새 기록(새 날짜)이 쌓인다. 같은 상품+판매처의 기록은 날짜순으로 이어져 가격 변동을 볼 수 있다.
- 비교 목록은 같은 상품+판매처 조합에서 **가장 최신 기록만** 기본 표시한다. "이전 기록 보기"로 펼칠 수 있다.
- 오프라인 판매처 기록은 "최신가격 다시 검색"을 숨기고 "이 기록으로 새로 등록"만 둔다.

**돌아와서 등록**
- 외부 탭에서 돌아오면 "온라인 가격 등록" 버튼(또는 화면 하단 고정 바)을 보여준다.
- 누르면 등록 화면이 **현재 상품 정보로 미리 채워진 상태**로 열린다.
  - 미리 채움: 품명, 품목, 원산지, 브랜드, 포장단위, 단위용량, 번들묶음.
  - 비움: 가격, 판매처, 배송비, 사진, 메모.
  - 날짜는 오늘.
- 판매처에 온라인몰을 고르면 배송비 입력란이 열린다.
- 사용자는 바뀐 항목만 수정한다. 예: 온라인은 번들 6개, 용량 다름 → 번들묶음, 단위용량만 고친다.
- 사진은 필수다. 온라인 가격 화면 캡처 또는 상품 이미지를 올린다. 앱 안에서 바로 캡처 업로드를 고를 수 있게 한다.
- 저장 후 비교 목록으로 돌아가 새 기록의 순위를 바로 보여준다.

**같은 원리를 오프라인에도 적용**
- 어떤 기록 상세에서든 "이 기록으로 새로 등록"(복제 등록)을 제공한다. 위 "미리 채움/비움" 규칙을 같게 쓴다.

## 8. 데이터 모델 (초안)
```
Item(품목)        id, name
Product(상품)      id, item_id, name|null(N/A), brand|null, origin_type(domestic|import|na),
                  origin_country|null, pack_unit, unit_amount|null, unit_type(g|ml|ea|null)
PriceRecord       id, product_id, bundle_count, price, shipping_fee|null,
                  store_id, purchased_at, photo_id, note|null, created_at
Store             id, name, is_online
Photo             id, blob/uri, created_at
```
- N/A는 null과 별도 플래그로 구분한다 (미입력 대 해당사항 없음).
- 단위가격은 저장하지 않고 조회 시 계산한다.
- 모든 레코드에 UUID, created_at, updated_at, 소유자 필드(향후 다중 사용자용)를 둔다.
- 향후 통합 DB를 위해 판매처는 이름 정규화 가능한 구조(체인, 지점)로 둔다.

## 9. 기술 가정 (변경 가능)
- PWA 모바일 웹앱. 홈 화면 추가 지원.
- MVP는 기기 로컬 저장 (IndexedDB). 서버 없음.
- 오프라인에서도 등록과 조회 가능 (마트 내 약한 통신 환경).
- 사진은 업로드 전 리사이즈/압축 (긴 변 1280px 정도).
- 언어: 한국어. 통화: 원.

## 10. 화면
1. **홈**: 맨 위에 "빠른 비교" 입력 (품명부터 입력, 자동완성, 15절), 그 아래 최근 기록, "가격 등록" 버튼.
2. **가격 등록**: 품명 → 품목 → 나머지 → 사진 순. 품명을 자동완성으로 고르면 그 상품의 이전 사진도 불러온다. 하단에 즉시 비교 결과.
3. **품목 비교 목록**: 정렬된 목록 + 필터 칩 + 프리셋 3종.
4. **기록 상세/수정/삭제**: 사진 확대, 값 수정.

## 11. 인수 기준
1. 사진 없이 저장할 수 없다.
2. 필수 7항목(사진, 품목, 포장단위, 번들묶음, 가격, 판매처, 날짜) 외는 "해당사항 없음"으로 저장된다.
3. 기존 품명을 고르면 품목/원산지/브랜드/단위용량/번들이 자동 입력된다.
4. 두부 300g×2 3,480원과 두부 400g×1 2,900원의 단위가격은 각각 580원/100g, 725원/100g로 계산되어 580원이 위에 나온다.
5. 브랜드, 원산지, 번들묶음 필터를 각각 여러 개 선택하면 조건에 맞는 기록만 남고 그중 최저가가 강조된다.
6. 온라인 판매처에서만 배송비 입력란이 보이고 단위가격에 반영된다.
7. 네트워크가 없어도 등록과 조회가 된다.
8. 모바일(폭 360px)에서 가로 스크롤 없이 모든 화면이 쓸 수 있다.
9. 온라인 기록이 하나도 없는 품목에서도 "온라인 가격 검색" 버튼이 동작하고, 검색어가 브랜드+품명+단위용량으로 채워진다.
10. 검색 후 "온라인 가격 등록"을 누르면 품명, 품목, 원산지, 브랜드, 포장단위, 단위용량, 번들묶음이 채워지고 가격, 판매처, 배송비, 사진은 비어 있다.
11. "이 기록으로 새로 등록"도 같은 방식으로 채워진 등록 화면을 연다.
12. 미리 채워진 값을 수정해도 원래 기록은 바뀌지 않는다.
13. "온라인 가격 검색"은 쇼핑몰이 아니라 구글 검색 결과를 새 탭으로 연다.
14. 온라인 기록 상세에서 "최신가격 다시 검색"을 누르면 구글이 열리고, 돌아와 등록하면 판매처와 배송비까지 채워지고 가격과 사진만 비어 있다.
15. 갱신 저장 후 같은 상품+판매처는 최신 기록만 목록에 보이고, "이전 기록 보기"로 과거 가격이 날짜순으로 보인다.
16. 오프라인 기록 상세에는 "최신가격 다시 검색"이 보이지 않는다.
17. 결과 화면의 모든 행에 사진, 단위가격, 가격, 용량×번들, 판매처, 날짜가 보이고 단위가격이 가장 크다.
18. 1위 행에 색과 "최저가" 배지가 함께 보인다.
19. 등록 화면에서 진입하면 내 상품 비교 바에 순위와 최저가 차이가 보인다.
20. 기록 0건, 필터 결과 0건일 때 7.4의 안내와 버튼이 보인다.
21. 90일 넘은 기록은 흐리게 표시되고 "오래된 가격"이 붙는다.
22. 단위가 다른 기록은 순위에 섞이지 않고 "비교 불가" 구역에 따로 나온다.
23. 사진이 있는 기존 상품을 품명 자동완성으로 고르면 그 상품의 가장 최근 사진이 사진 칸에 "이전 사진"으로 채워지고, 사진을 새로 올리지 않아도 저장할 수 있다.
24. 불러온 사진을 "다시 촬영" 또는 "갤러리에서 선택"으로 바꾸면 새 사진이 저장되고 이전 기록의 사진은 그대로다.
25. 이전 사진이 없는 상품을 고르면 사진 칸이 비어 있고 사진 없이는 저장할 수 없다.
26. "온라인 가격 등록", "이 기록으로 새로 등록", "최신가격 다시 검색"으로 열린 등록 화면은 사진 칸이 비어 있다.
27. 폭 360px에서 프리셋 탭 세 개, 필터 버튼 세 개, 하단 고정 버튼의 글자가 모두 한 줄로 보이고 줄바꿈되거나 잘리지 않는다.
28. 프리셋 탭의 이름은 "똑같은 상품", "용량 무관", "품목 전체"이고, 선택한 탭의 전체 뜻이 탭 아래 한 줄 설명으로 보인다.
29. 결과 목록의 각 행은 카드로 보이고, 1위 카드는 색, 테두리, "최저가" 배지로 다른 카드와 구분된다.
30. 모든 글자와 배경의 명암비가 4.5:1 이상이다 (큰 글자는 3:1).
31. 홈, 등록, 결과, 상세 화면이 13절의 색, 글자 크기, 간격 규칙을 같이 쓴다 (화면마다 다른 값이 없다).
32. 폭 360px 화면 캡처 4장(홈, 등록, 결과, 상세)이 `docs/screenshots/`에 저장되어 있다.

## 13. 시각 디자인
목표: 마트 안에서 한 손으로 빠르게 읽히는, 깔끔하고 믿음이 가는 화면. 지금은 기능 위주라 투박하다. 아래 규칙으로 모든 화면을 같은 모양으로 맞춘다.

### 13.1 디자인 원칙
1. **가격이 주인공이다.** 화면에서 가장 크고 굵은 글자는 단위가격이다.
2. **한 화면에 한 가지 강조.** 강조색은 최저가, 주요 버튼에만 쓴다.
3. **줄바꿈 없는 컨트롤.** 버튼, 탭, 칩의 글자는 한 줄이다. 길면 이름을 줄이고 설명은 따로 둔다.
4. **여백으로 나눈다.** 선을 많이 긋지 않고 카드와 간격으로 묶는다.

### 13.2 색 (토큰으로 한 곳에 정의, 화면에서 직접 색 값을 쓰지 않는다)
| 토큰 | 용도 | 값(제안) |
|---|---|---|
| `--primary` | 주요 버튼, 선택된 탭 | 진한 초록 `#1F7A4D` 유지 |
| `--primary-soft` | 선택된 칩, 1위 카드 배경 | 연한 초록 `#E7F3EC` |
| `--accent` | "최저가" 배지, 가격 하락 | 따뜻한 주황 `#E8590C` 계열 |
| `--bg` | 앱 배경 | `#F6F7F6` |
| `--surface` | 카드, 입력 | `#FFFFFF` |
| `--text`, `--text-sub` | 본문, 보조 글자 | `#1A1A1A`, `#5F6368` |
| `--line` | 얇은 구분선 | `#E3E6E4` |
| `--danger` | 오류, 삭제 | `#C0392B` |
- 글자와 배경의 명암비는 4.5:1 이상 (큰 글자는 3:1). 색만으로 상태를 구분하지 않는다.

### 13.3 글자
| 용도 | 크기/굵기 |
|---|---|
| 단위가격 (목록 행) | 22px, 굵게, 숫자 폭 고정(tabular-nums) |
| 화면 제목 | 20px, 굵게 |
| 본문 | 16px |
| 보조 (판매처, 날짜, 설명) | 13~14px, `--text-sub` |
| 버튼, 탭, 칩 | 14~15px, 한 줄 |
- 글꼴은 시스템 한글 글꼴(Apple SD Gothic Neo, Noto Sans KR). 줄 높이 1.4~1.5.
- 가격은 천 단위 쉼표와 단위(원, /100g)를 함께 보이고 단위는 작게 쓴다.

### 13.4 간격과 모양
- 간격은 4px 배수 (4, 8, 12, 16, 24). 화면 좌우 여백 16px.
- 카드 모서리 16px, 버튼과 입력 12px, 칩과 탭 999px(알약).
- 그림자는 아주 옅게 한 가지 (카드, 하단 바). 터치 대상 44px 이상은 유지한다.

### 13.5 컴포넌트 규칙
**프리셋 탭 (7.1 영역 C)**
- 세 칸이 폭을 똑같이 나누는 분할 컨트롤. 선택된 칸은 `--primary` 배경에 흰 글자.
- 이름은 "똑같은 상품" / "용량 무관" / "품목 전체". 줄바꿈 금지. 폭이 모자라면 글자 크기를 줄이지 말고 이름을 줄인다.
- 선택된 탭의 전체 뜻을 탭 아래에 13px 설명 한 줄로 보인다: 예) "같은 상품, 용량 무관" → "품명과 브랜드가 같은 상품을 단위가격으로 비교해요".
- 비활성 탭(내 상품 없음)은 흐리게 하고 탭하면 이유를 한 줄로 알려 준다.

**필터 바 (영역 D)**
- 필터 버튼 세 개(브랜드, 원산지, 번들)는 알약 모양, 한 줄. 선택값이 있으면 개수 배지(예: "브랜드 2")를 붙인다.
- 선택 목록은 아래에서 올라오는 시트로 연다. 적용된 필터 칩은 가로로 스크롤한다.

**결과 카드 (영역 E)**
- 행마다 카드. 왼쪽 64px 정사각 사진(모서리 12px), 오른쪽에 단위가격(가장 큼), 그 아래 가격·용량×번들, 품명·브랜드, 맨 아래 판매처·날짜.
- 순위는 사진 모서리의 작은 번호 배지로 둔다.
- 1위 카드: `--primary-soft` 배경, `--primary` 테두리 2px, `--accent` "최저가" 배지. 내 상품 카드는 "내 상품" 라벨.
- 오래된 가격은 날짜 옆에 작은 "오래된 가격" 라벨로 표시하고 카드 전체를 흐리게 하지 않는다 (읽기 쉬워야 한다).

**하단 고정 바 (영역 G)**
- 흰 배경, 위쪽 옅은 그림자, 아이폰 하단 안전 영역(safe area) 여백 포함. 주요 버튼 하나(가격 등록, `--primary` 채움)와 보조 버튼 하나(온라인 가격 검색, 테두리).

**버튼 위계**
- 주요: 채운 `--primary`. 보조: 흰 바탕 + 테두리. 3차: 글자만. 위험: `--danger`. 한 화면에 주요 버튼은 하나.

**등록 화면**
- 항목을 카드 세 개로 묶는다: "상품 정보"(품명~단위용량), "가격 정보"(번들, 가격, 판매처, 배송비, 날짜), "사진".
- 필수는 라벨 옆 작은 점(●)으로, "해당사항 없음"은 입력칸 오른쪽의 토글 알약으로 둔다.
- 이전 사진은 사진 카드 위에 "이전 사진" 라벨과 함께 크게 보여 준다.
- 내 상품 비교 바는 화면 아래에 고정되고 순위와 차이를 가장 크게 보인다.

**빈 상태, 불러오는 중**
- 빈 상태는 큰 아이콘(이모지 가능) + 한 줄 안내 + 주요 버튼 하나. 불러오는 중은 카드 모양 스켈레톤.

**움직임**
- 탭, 시트, 버튼 눌림만 150~200ms로 부드럽게. "움직임 줄이기" 설정을 따른다.

### 13.6 범위 밖 (MVP)
- 다크 모드, 로고 제작, 커스텀 글꼴 파일, 복잡한 애니메이션.

### 13.7 발표자료
- 디자인을 고친 뒤 `docs/screenshots/`의 화면 캡처 4장(폭 360px)으로 `PRESENTATION.pdf`의 앱 화면을 다시 만든다.

## 14. 데모 모드 (제출 영상 촬영용)
목표: 빈 상태가 아니라 샘플 데이터가 들어 있는 앱으로 제출 영상을 촬영한다. 일반 사용자 앱에는 영향이 없어야 한다.

### 14.1 실행
- `npm run demo` 한 번으로 데모용 빌드를 만들고 `http://127.0.0.1:4174`에서 미리보기를 연다 (포트 4174 고정, 일반 미리보기 4173과 다르다).
- 포트가 다르면 브라우저 저장소(IndexedDB)도 분리되므로 평소 쓰는 데이터와 섞이지 않는다.
- 일반 빌드(`npm run build`)에는 샘플 데이터 코드와 사진이 들어가지 않는다.

### 14.2 샘플 데이터
- 처음 열 때 저장소가 비어 있으면 샘플을 자동으로 넣는다. 이미 데이터가 있으면 넣지 않는다.
- 주소 끝에 `?reset=1`을 붙이면 저장소를 비우고 샘플을 다시 넣는다. 촬영을 다시 시작할 때 쓴다.
- 날짜는 오늘 기준 상대값(예: 오늘, 3일 전, 40일 전, 120일 전)으로 만든다. 언제 열어도 "오래된 가격"(90일 초과) 예시가 하나 이상 보여야 한다.
- 품목은 5개 이상, 기록은 25건 이상이다. 품목 예: 두부, 우유, 계란, 사과, 라면.
- 두부는 영상의 중심이다. 기록 8건 이상, 아래를 모두 포함한다.
  - 같은 상품에서 용량·번들이 다른 기록 (예: 300g×2, 400g×1, 300g×4)
  - 브랜드 3개 이상 (노브랜드, 풀무원, 맑은물에 등), 국산과 수입 모두
  - 온라인 기록 2건 이상 (배송비 있는 것 1건, 같은 상품+판매처의 이전 가격 이력 1건)
  - 오프라인 판매처 (이마트 구로점, 동네시장 등)
  - 90일이 넘은 기록 1건
  - 단위가 다른 기록 1건 (비교 불가 구역 예시)
  - 최저가가 필터에 따라 달라지는 구성 (예: 국산만 고르면 1위가 바뀐다)
- 영상 촬영 때 보여 줄 입력 예시: 두부 300g×2 3,480원을 입력하면 순위가 "n건 중 4~5위"쯤 나오도록 가격을 짠다.

### 14.3 샘플 사진
- 사진은 앱이 직접 그린 이미지(색 배경 + 상품명 글자)를 쓴다. 외부 이미지, 저작권 있는 사진은 쓰지 않는다.
- 사진 파일은 레포에 따로 올리지 않고 코드로 만든다 (캔버스로 그려 저장).
- 기록마다 사진이 있어야 한다 (사진 필수 규칙 유지).

### 14.4 표시
- 데모 모드에서는 화면 맨 위 구석에 눈에 띄지 않는 "데모 데이터" 작은 표시를 둔다. 영상에 나와도 괜찮을 만큼 작고 옅게 한다. 데모 모드가 아니면 보이지 않는다.

### 14.5 인수 기준
33. `npm run demo`를 실행하면 4174번 포트에서 앱이 열리고 첫 화면에 샘플 품목 5개 이상이 보인다.
34. 두부 비교 목록에서 14.2의 구성(번들 다름, 브랜드 3개 이상, 온라인 2건 이상, 오래된 가격, 비교 불가, 이력)이 모두 보인다.
35. `?reset=1`로 열면 데이터가 초기 샘플 상태로 돌아간다.
36. 일반 빌드와 일반 미리보기(4173)에는 샘플 데이터가 없다.
37. 샘플 기록에는 모두 사진이 있고 외부 이미지 파일을 쓰지 않는다.

## 15. 홈 빠른 비교와 자동완성 후보
목표: 마트에서 앱을 열자마자 품명만 입력하면 나머지가 채워지고, "똑같은 상품"과 "용량 무관" 탭을 바로 쓸 수 있다.

### 15.1 홈 빠른 비교 입력
- 홈 맨 위에 입력 카드를 둔다. **첫 입력칸은 품명이다.** 포커스는 홈을 열면 품명 칸에 자동으로 있지 않아도 되고, 칸이 가장 위에 크게 보이면 된다.
- 품명을 입력하면 자동완성 후보 목록(15.2)이 열린다.
- 후보를 고르면 아래 칸이 한 번에 채워진다. 모두 고칠 수 있다.

| 칸 | 채움 | 비고 |
|---|---|---|
| 품명 | 후보의 품명 | |
| 품목 | 후보의 품목 | 품명이 "해당사항 없음"인 후보는 품목으로 찾는다 |
| 브랜드 | 후보의 브랜드 | "해당사항 없음" 가능 |
| 포장단위 | 후보의 포장단위 | |
| 단위용량 | 후보의 단위용량 | |
| 번들묶음 | 후보의 번들묶음 | |
| 가격 | 후보의 가장 최근 가격 | "이전 가격" 표시. 오늘 본 가격으로 고쳐서 쓴다 |
- 원산지는 입력칸에 보이지 않지만 후보의 값을 그대로 가져가 비교에 쓴다. 필요하면 "원산지 바꾸기"로 고친다.
- 후보를 고르지 않고 직접 입력해도 된다 (처음 보는 상품). 이 경우 품목은 필수, 나머지는 비워도 된다.
- 두 버튼이 있다.
  - **"비교하기"**: 저장하지 않고 결과 화면으로 간다. 입력한 값이 "내 상품"이 된다.
  - **"이 가격으로 등록"**: 등록 화면으로 간다. 입력한 값이 채워지고, 사진은 후보의 이전 사진이 채워진다 (3-1).

### 15.2 자동완성 후보 목록 (드롭다운)
후보 한 줄은 상품을 정확히 골라낼 수 있도록 아래 정보를 모두 보인다.

| 위치 | 정보 | 예 |
|---|---|---|
| 왼쪽 | 사진 썸네일 56px | |
| 1줄 (굵게) | 품명 (입력과 일치하는 글자 강조) | 국산콩으로 만든 두부 |
| 2줄 | 품목 · 브랜드 · 원산지 | 두부 · 노브랜드 · 국산 |
| 3줄 | 용량×번들 · 최근 가격 · 단위가격 | 300g×2 · 3,480원 · 580원/100g |
| 4줄 (작게) | 최근 판매처(온라인이면 배지) · 날짜 · 기록 건수 | 이마트 구로점 · 3일 전 · 기록 5건 |
- 후보 한 개는 "상품 + 번들묶음" 조합의 가장 최근 기록 한 건이다. 같은 상품의 300g×2와 300g×4는 서로 다른 후보다.
- 품명이 "해당사항 없음"인 상품(예: 농산품)은 1줄에 품목명을 쓴다.
- 일치 방식: 입력한 글자가 품명, 품목, 브랜드 어디에든 들어 있으면 후보가 된다 (앞부분 일치가 먼저).
- 정렬: 앞부분 일치 → 최근 날짜 → 기록 건수 순. 최대 8개를 보이고 더 있으면 "더 보기".
- 후보가 없으면 "처음 보는 상품이에요. 직접 입력하세요" 한 줄을 보인다.
- 한 줄의 높이는 56px 이상, 한 줄 글자는 줄바꿈 대신 말줄임(…)으로 줄인다. 단위가격과 번들은 말줄임 대상이 아니다.
- 같은 정보가 보이는 후보가 둘이면 판매처나 날짜로 구별되게 4줄이 항상 보인다.

### 15.3 결과 화면과의 연결
- 후보를 골라 "비교하기"로 오면 결과 화면의 "내 상품"은 입력한 값이다. 그래서 "똑같은 상품"과 "용량 무관" 탭이 처음부터 켜져 있다. (홈에서 품목만 고를 때만 두 탭이 꺼진다.)
- 내 상품 비교 바(영역 B)가 보이고, 입력한 가격의 순위와 최저가 차이를 알려 준다.
- 기본 탭은 "똑같은 상품"이다. 같은 상품 기록이 하나도 없으면 "품목 전체"로 시작한다.
- 결과 화면에서 "이 가격으로 등록"을 누르면 등록 화면으로 갈 수 있다.

### 15.4 등록 화면과의 일치
- 등록 화면 품명 자동완성도 15.2의 후보 목록을 똑같이 쓴다 (같은 정보, 같은 정렬).
- 등록 화면에서 후보를 고르면 가격도 "이전 가격"으로 채워진다 (5절 3).

### 15.5 인수 기준
38. 홈을 열면 첫 입력칸이 품명이고, 품명을 입력하면 자동완성 후보 목록이 열린다.
39. 후보를 고르면 품명, 품목, 브랜드, 포장단위, 단위용량, 번들묶음, 가격이 한 번에 채워지고 모두 고칠 수 있다.
40. 후보 한 줄에 사진, 품명, 품목, 브랜드, 원산지, 용량×번들, 최근 가격, 단위가격, 판매처, 날짜, 기록 건수가 모두 보인다.
41. 같은 상품의 번들이 다른 기록은 별개의 후보로 나오고 한 줄만 봐도 구별된다.
42. "비교하기"를 누르면 저장 없이 결과 화면으로 가고, "똑같은 상품"과 "용량 무관" 탭이 켜져 있고 내 상품 비교 바가 보인다.
43. 후보를 고르지 않고 직접 입력해도 품목만 있으면 비교할 수 있다.
44. 등록 화면 품명 자동완성에서도 같은 후보 정보가 보이고 가격이 "이전 가격"으로 채워진다.
45. 후보가 없으면 "처음 보는 상품이에요" 안내가 보인다.
