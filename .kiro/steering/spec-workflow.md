# 스펙 작업 규칙

이 프로젝트의 스펙은 `.kiro/specs/<이름>/`에 있다. 스펙을 쓰는 봇과 구현하는 봇이 따로 일한다.

## 파일
| 파일 | 내용 |
|---|---|
| `spec.md` | 전체 배경, 화면, 인수 기준 |
| `requirements.md` | 요구사항과 인수 기준 (번호가 기준점) |
| `design.md` | 구조, 인터페이스, 데이터 모델, 테스트 전략 |
| `tasks.md` | 구현 순서. 완료하면 `[ ]`를 `[x]`로 바꾼다 |
| `questions.md` | 막혔을 때 질문 (아래 참고) |

## 상태 (각 파일 맨 위 `status:` 줄)
- `status: ready`: 구현해도 된다.
- `status: blocked`: 스펙 봇의 답을 기다린다. 구현하지 않는다.

## 스펙 봇 규칙
- 스펙과 문서만 쓴다. 구현 코드를 쓰지 않는다.
- `status: blocked`를 보면 `questions.md`에 답을 쓰고 `status: ready`로 되돌린다.

## 구현 봇 규칙
- `status: ready`인 스펙만 구현한다.
- `tasks.md` 순서대로 진행하고 작업이 끝나면 `[x]`로 표시한다.
- 스펙 내용을 직접 고치지 않는다. 모호하거나 모순이면 구현을 멈춘다.
  1. 해당 스펙의 `spec.md` 맨 위를 `status: blocked`로 바꾼다.
  2. `questions.md`에 질문을 쓴다. 어느 요구 번호인지, 선택지, 추천안을 적는다.
  3. 막히지 않은 다른 작업은 계속한다.
- `status`가 다시 `ready`가 되면 `questions.md`의 답을 읽고 이어서 한다.
- 구현이 `requirements.md`의 인수 기준을 만족하는지 테스트로 확인한다.
